# v0.3.2 performance audit: quality-preserving hot path

This pass treats image quality as a hard invariant. UniversalDLSS5 does **not** lower the resolution of the color image submitted to Feature 18 and does **not** upscale a cheaper neural result as a production performance mode. Reduced-resolution work remains limited to auxiliary guide generation such as the explicit HLSL optical-flow fallback.

## Changes in this pass

- Direct Feature-18 GPU timing now uses D3D12 timestamp queries. Two 64-bit timestamps are resolved per frame slot and read only after the slot completion fence. The old CPU wall-clock value is no longer reported as GPU time.
- Synchronized pacing no longer copies the just-produced neural frame into the asynchronous stale-output cache. The cache itself is allocated only for adaptive/asynchronous pacing.
- Direct NGX fence waits reuse one event instead of creating and destroying a Win32 event on every synchronized frame.
- Neural ring resources are lazy: the full-resolution refinement scratch surface exists only for 2x+ passes, and the control-mask surface exists only when an explicit game control mask is actually supplied.
- D3D11 no longer maintains the reduced-resolution HLSL optical-flow history unless the explicit HLSL optical-flow mode is selected.
- Shader-readable source resources bypass the redundant D3D11 working-copy hop. The D3D12On12 owned color staging resource is now created shader-readable so that path benefits too.
- D3D11 backbuffer SRVs and RTVs are cached instead of recreated each Present.
- Negative lookup of `UniversalDLSS5.GameGuides.dll` is cached instead of probing the filesystem every Present.
- D3D12 late-attach command-list touch discovery is disabled after all registered D3D12 swapchains have a trusted presentation queue and re-enabled when an unproven swapchain appears.

At 3840x2160, one 32-bit full-resolution texture is about 31.6 MiB. With the default three active neural slots, avoiding unused scratch plus unused control-mask surfaces removes up to about 190 MiB of unnecessary allocation in the common 1x/no-explicit-mask case. Synchronized mode also avoids the separate ~31.6 MiB completed-output cache at 4K.

## Remaining high-value bottlenecks

### 1. D3D12On12 compatibility path

The D3D12 game path still performs a game-backbuffer -> owned-color copy, D3D11On12 acquire/release, an immediate-context Flush, then an owned-color -> game-backbuffer copy. The long-term fast path should be a native D3D12 preprocessing/postprocessing implementation feeding Feature 18 directly.

### 2. Full-resolution D3D11 pre/post traffic

The current pipeline still converts source color to FP16, creates the bounded Feature-18 proxy, generates full-resolution depth/motion/mask data, runs post composition, and copies full-resolution history. The synthetic protection mask is only used by local post-composition, so a future exact shader fusion of mask generation into post-composition can remove one dispatch and one mask surface without reducing NR resolution.

### 3. Heuristic tracker cost

D3D11 tracking hooks still observe several hot API calls and draw calls. D3D12 candidate tracking still inspects transition barriers even after presentation-queue discovery is disabled. A discovery -> locked -> revalidate state machine should put heuristic trackers to sleep once trusted native game guides are stable, waking only on resource destruction/resize/lifetime failure.

### 4. Shared-resource copies into the NGX ring

The direct Feature-18 backend still copies full-resolution color/motion/depth from D3D11 resources into each shared D3D11/D3D12 slot. A native D3D12 path can make the neural slot resources the canonical working resources and eliminate these extra transfers for D3D12 games.

### 5. Serialized synchronized pacing

Synchronized mode intentionally waits for the current neural result, so Feature-18 latency remains directly visible in frame time. The new timestamp telemetry separates neural GPU execution from CPU pacing wait. Further scheduling work should reduce bubbles without presenting arbitrarily stale frames.

## Profiling interpretation

`Feature-18 GPU time` now measures the D3D12 interval around the base Feature-18 evaluation plus any requested refinement passes. `Frame pacing wait` remains CPU-visible wait time. Neither value by itself is the total UniversalDLSS5 GPU cost; native D3D12 pre/post timestamps are the next profiler extension once the compatibility path is replaced.

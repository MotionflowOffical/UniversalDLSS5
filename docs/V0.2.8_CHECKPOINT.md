# UniversalDLSS5 v0.2.8 source checkpoint

Date: 2026-09-12

This checkpoint preserves the direct in-game Neural Rendering architecture built on top of the v0.2.7 temporal-reprojection source.

## Implemented

- `Direct in-game NR` is the default backend.
- A D3D11 render-resource tracker observes render/depth targets, shader resources, clears and draw usage without CPU pixel readback.
- D3D11 shader reflection detects semantic motion-vector resources, including Unity `_CameraMotionVectorsTexture`.
- D3D11 shader/constant-buffer tracking extracts candidate view/projection matrices without arbitrary process-memory scanning.
- Real scene depth can be recovered from the dominant DSV used during the completed frame, even if the game unbinds it before `Present`.
- Camera + depth motion reconstruction emits current-to-previous motion vectors in pixel units.
- Game-native motion is preferred over camera reconstruction; NVOFA, HLSL flow and zero motion are lower-priority fallbacks.
- Low-resolution optical-flow history is refreshed every rendered frame so switching away from and back to flow does not use stale history.
- An in-game Streamline feature-1004 path uses a same-adapter D3D12 device/queue, real D3D12 command lists, unique Streamline frame tokens, constants and local resource tags.
- The in-game signed feature-18 path uses `nvngx.dll_UniversalDLSS5_NRForwarder.dll`, preserving the caller-compatible path already validated on the user's RTX 4060.
- If direct in-game initialization fails, the existing external NRHost path is tried automatically before passthrough.
- D3D11/D3D12 shared textures use NT handles with keyed-mutex compatibility; frame pixels remain GPU-only.
- Diagnostics expose execution location, backend kind, native-motion candidate score, camera-matrix confidence, depth provenance and temporal-history state.

## Runtime files

Required for the already-proven signed feature-18 route:

- `runtime/nvngx_dlssnr.dll` (user supplied; not redistributed)

Optional Streamline feature-1004 route:

- `runtime/sl.interposer.dll`
- `runtime/sl.common.dll`
- `runtime/sl.dlss_nr.dll`
- `runtime/nvngx_dlssnr.dll`

If the Streamline plugin set is incomplete, UniversalDLSS5 falls back to the signed feature-18 route.

## Known limitations / not yet runtime-validated

1. This Linux build environment cannot compile or run the native Windows D3D11/D3D12/NGX targets. MSVC compilation on Windows is still required.
2. TheLongDrive has not yet been run with this v0.2.8 direct-mount checkpoint.
3. Automatic native motion/depth/camera discovery is currently D3D11-focused. The D3D12 source path does not yet have an equivalent native G-buffer tracker.
4. Manual persistence of a selected native-motion candidate by stable per-game signature is not implemented yet.
5. NVOFA is a fallback, but full forward/backward consistency validation is not yet implemented.
6. Streamline feature 1004 cannot be runtime-tested without an authorized `sl.dlss_nr.dll`.
7. Camera tracking currently carries the selected current view-projection matrix into the next frame as previous-frame state; explicit engine-provided previous-VP consumption is not fully generalized yet.
8. Normals/albedo are not bound to undocumented DLSS-NR parameters.
9. Streamline `slDLSSNRSetOptions` tuning is not yet wired; the signed feature-18 route remains the fully tuned path.
10. Native motion encoding outside explicitly recognized contracts remains a candidate only and is never silently consumed.

## Portable verification target

The source package is expected to pass:

- the full portable CTest suite,
- `tools/audit_no_readback.py`,
- `tools/verify_package.py`.

These checks validate source architecture and policy; they are not a substitute for a native Windows compile/runtime test.

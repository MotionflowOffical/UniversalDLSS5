# v0.2.8 Modern UI and synchronized pacing update

This update targets two independent failures observed after the stable-renderer scheduler work.

## Frame-pacing correction

The previous asynchronous policy could present the most recent completed neural frame while the game simulation continued to advance. Under heavy 2x-4x Feature-18 load that result could become several Presents old, which appeared as long trails, delayed camera response, or smearing rather than an ordinary FPS reduction.

The default is now **Synchronized**. The current source frame is submitted as one atomic Feature-18 job (including all requested refinement passes), the bridge waits for that job's D3D12 completion fence, and only then copies its output for the current Present. If neural processing is slower, delivered FPS drops rather than image age growing.

Two opt-in alternatives remain:

- **Adaptive** may use a completed result only while it is at most one Present old; otherwise it synchronizes to the current frame.
- **Asynchronous** retains latest-completed behavior for maximum throughput and explicitly accepts the possibility of visible trailing under sustained overload.

Runtime diagnostics now report pacing mode, neural-output age in frames and milliseconds, and CPU wait time attributable to synchronized pacing.

## Weak-guide temporal protection

Feature 18 cannot reconstruct correct temporal correspondence from zero motion and synthetic far depth. When no trusted native/camera motion and no real depth are present, the bridge marks the neural evaluation reset for the frame rather than allowing unsupported history to accumulate. This is intentionally conservative for games such as The Long Drive until better game guides are available.

## Controller rewrite

The controller no longer constructs its interface from stock Win32 tab, trackbar, combo-box, and multiline-edit child controls. It keeps one native top-level window and renders the interface using **Direct2D + DirectWrite**:

- six-page sidebar navigation;
- DPI-aware anti-aliased typography;
- rounded cards, buttons, segmented choices, toggles, and sliders;
- System / Light / Dark neutral themes;
- a custom-rendered diagnostics page with copy/save actions;
- responsive vertical scrolling instead of fixed pixel-positioned child widgets;
- live pacing/age/queue telemetry cards.

Process-tree maintenance remains on the background worker rather than the UI polling path.

## Verification boundary

Portable policy/wiring tests and source audits can be run in the Linux packaging environment. Native Windows D3D11/D3D12/NGX compilation and RTX Feature-18 behavior still require the Windows/MSVC target machine.

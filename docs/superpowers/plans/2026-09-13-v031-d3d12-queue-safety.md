# UniversalDLSS5 v0.3.1 D3D12 Queue Safety Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop D3D12 games such as Hitman from being processed through an unproven DIRECT queue or direct D3D11On12 backbuffer wrap, add crash-stage telemetry, and publish the result as v0.3.1 everywhere.

**Architecture:** D3D12 command-list barrier observation records which swapchain backbuffers each command list touches. ExecuteCommandLists then attributes that work to a concrete DIRECT queue; two consecutive proofs (or exact queue capture at swapchain creation) are required before D3D11On12 starts. The D3D11On12 pipeline processes an injector-owned staging color texture and copies it to/from the game backbuffer on the proven queue, avoiding a direct D3D11On12 wrapper around the game-owned swapchain resource.

**Tech Stack:** C++20, DXGI, D3D12, D3D11On12, MinHook, CMake/CTest, CPack/NSIS.

**Spec:** Approved in chat on 2026-09-13 after Hitman continued to crash with motion/depth disabled.

## Global Constraints

- Current public version is 0.3.1 / 0.3.1.0.
- Never initialize D3D11On12 from a merely recent same-device queue.
- D3D12 processing must stay passthrough until queue ownership is proven.
- Keep the working game-guide capture path and synchronized pacing behavior.
- No proprietary NVIDIA DLLs in source/release packages.

# v0.2.8 ghosting / color debug fix

Date: 2026-09-12

This patch targets the The Long Drive failure signature observed in diagnostics:

- D3D11 source, D3D12 Feature-18 NR path active
- feature creation/evaluation succeeds (`0x00000001`)
- no game camera matrices or trusted game-native motion
- synthetic far depth
- motion path falls through to the coarse HLSL block matcher
- severe temporal speckle/ghosting with motion, but a clean image with zero motion

## Root causes addressed

### 1. Auto mode was treating the coarse HLSL block matcher as production motion

The HLSL fallback estimates one motion vector per low-resolution block from a small local patch search. It has no forward/backward consistency test, no dense spatial regularization, and only a simple confidence heuristic. Feeding those vectors into a temporal neural renderer can create exactly the high-frequency edge speckle and trails seen in the failing screenshots.

`Auto` no longer falls through to HLSL. Its safe order is now:

1. explicit GameGuides native motion
2. tracked game-native motion
3. camera + real depth reconstruction
4. NVIDIA Optical Flow Accelerator
5. zero motion

The HLSL route remains available only through the explicit `Optical flow (NVOFA/HLSL experimental)` setting.

### 2. A synthetic mask derived from the same approximate motion was being sent to Feature 18

The internally generated mask is useful for the injector's own final compositing, but it is not an authoritative game-supplied NR control mask. Passing it to Feature 18 can compound a bad optical-flow estimate: the incorrect motion changes the residual mask, and the mask then influences the temporal neural feature again.

The patch keeps the synthetic mask for local composition, but only binds `DLSSNR.ControlMask` when a GameGuides adapter explicitly provides a mask with a validated convention.

### 3. SDR sRGB swapchains could enter Feature 18 in the wrong transfer domain

When the source backbuffer is a typed `*_SRGB` resource, D3D11 shader reads decode it to linear automatically. The working pipeline representation should remain linear, but the RGBA8 neural proxy needs the stored SDR values expected by the signed Feature-18 path.

The patch now:

- keeps `current_` linear for local processing,
- re-encodes linear -> sRGB when producing the RGBA8 neural input for an sRGB source,
- decodes the neural RGBA8 result sRGB -> linear before sharpening/compositing,
- lets the final sRGB RTV perform the normal output encoding.

Non-sRGB swapchains keep the previous path.

### 4. Default private NR tuning was not a neutral baseline

The previous defaults included intensity 0.85, local tone 0.45, skin structure -1, AutoMask on, UI correction on, and only 0.80 final neural blend. Those are poor defaults for determining whether the raw Feature-18 path itself is healthy.

Fresh profiles now use a neutral diagnostic baseline:

- NR intensity: 1.0
- local tone: 1.0
- local structure: 1.0
- skin structure: 0.0
- AutoMask: off
- UI correction: off
- temporal/final NR blend: 1.0

Version-6 profiles automatically migrate only values that still exactly match the old defaults; user-customized values are preserved.

### 5. Difference visualization was too weak

The `Difference` view is now amplified x10 instead of x4 so subtle same-resolution NR changes are easier to verify.

## DLL placement

`UniversalDLSS5.Bridge.dll` does not need to be copied into the game folder. The controller launches the injector with the bridge's absolute path.

`nvngx.dll_UniversalDLSS5_NRForwarder.dll` also does not need to be in the game folder. The in-game NGX backend looks for it in the parent directory of the selected `runtime` directory (normally `build\\x64\\bin\\Release`).

The observed backend message `Direct in-game DLSS 5 active through signed feature 18 forwarder` proves that the forwarder was already found and used in the failing run.

## Expected The Long Drive result after rebuilding

With Motion = `Auto` and no native/camera/NVOFA guide available, diagnostics should now report:

- `Motion path: Zero motion vectors`
- `NR control mask: OFF`
- Feature 18 created: OK
- Feature 18 evaluated: OK
- Output composited: OK

This is deliberately a conservative baseline. If it is clean and correctly exposed, use `Original / NR split` and `Difference` to establish what the neural feature is actually changing. Do not judge enhancement from the HLSL optical-flow mode until the motion estimator is replaced or substantially upgraded.

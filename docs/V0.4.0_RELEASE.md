# UniversalDLSS5 v0.4.0

v0.4.0 is the **Universal Renderer Compatibility** release. It expands source-renderer coverage while preserving the established D3D11/D3D12 fast paths for games that already work.

## Renderer routing

The bridge now classifies the renderer into an explicit route rather than treating every non-D3D11/D3D12 application as unsupported:

- `NativeD3D11`
- `NativeD3D12`
- `ModernD3D12Recovery`
- `CompatD3D10`
- `CompatD3D9Ex`
- `CompatD3D9Classic`
- `CompatOpenGL`
- `CompatVulkan`

Native D3D11/D3D12 frames bypass the compatibility dispatcher. Runtime counters expose native, compatibility, legacy-copy, and external-host frames so regressions can be detected.

## 32-bit Feature 18

32-bit games use the x86 injector/bridge but route Neural Rendering through the x64 `UniversalDLSS5.NRHost.exe`. The external-host protocol carries renderer route, source API, game bitness, resource generation, full-resolution shared resources, and synchronization metadata.

This keeps the NVIDIA Feature 18 backend D3D12/x64 while allowing x86 games to use the real neural backend. Classic D3D9 uses a dedicated transfer route when GPU sharing is not available.

## Modern D3D12 recovery

Modern engines that expose DXGI/D3D12 but cannot prove the exact swapchain-creation queue no longer execute injected work directly on an inferred game queue. The recovery path now:

- tracks game queues whose command lists transition/touch the current swapchain backbuffer;
- signals a dedicated fence after each relevant game-queue submission;
- snapshots the current frame's queue dependencies at Present;
- creates a UniversalDLSS5-owned DIRECT queue on the same D3D12 device;
- makes that private queue wait on every relevant game-queue fence before touching the backbuffer;
- runs the recovery neural path through the x64 `UniversalDLSS5.NRHost.exe`;
- completes the injected post-copy before calling DXGI Present.

Only an exact queue captured from swapchain creation remains on the asynchronous `NativeD3D12` fast path. Heuristic D3D12 depth resources are not imported on the recovery route; only Present-safe captured guides or synthetic guides are used there.

**Half Sword** and **Teardown** are primary validation targets for this late-attach recovery path.

## D3D10 compatibility

D3D10/10.1 frames use a full-resolution shared D3D10 texture opened by a same-adapter D3D11 device. The existing canonical Feature 18 pipeline processes the shared surface and returns the result to the game renderer.

## D3D9 compatibility

Two D3D9 paths are provided:

- **D3D9Ex:** uses shared GPU resources where supported.
- **Classic D3D9:** hooks both `IDirect3DDevice9::Present` and `IDirect3DSwapChain9::Present`, then uses an isolated multi-slot full-resolution transfer ring because ordinary D3D9 backbuffers do not provide the resource-sharing model available in D3D9Ex/newer APIs.

The classic path is deliberately isolated so its additional copy/synchronization cost cannot affect modern games.

**Call of Duty 4: Modern Warfare** is the primary 32-bit classic-D3D9 validation target.

## OpenGL compatibility

OpenGL first attempts NVIDIA WGL/D3D interop with the D3D11 canonical surface. If that path cannot be established, an application-framebuffer PBO transfer fallback is available. It does not capture the desktop or use a screen-capture overlay.

## Vulkan compatibility

The Vulkan frontend hooks the loader/device/swapchain/present lifecycle and uses Win32/D3D11 external-memory interoperability when the Vulkan device exposes the required capability. Explicit image copies and synchronization surround the compatibility processing only for Vulkan games.

Late attachment to a Vulkan renderer whose device/queue lifecycle can no longer be reconstructed may stay in passthrough until renderer/swapchain recreation or an earlier attach.

## Safer detach

All hook families participate in the shared quiescence lifecycle. If in-flight graphics calls do not drain safely, detach can select `DetachedResident` instead of force-unloading live hook/trampoline or renderer state. The bridge becomes forwarding-only and remains resident until process exit.

This behavior is particularly important for logs that showed access violations after neural processing had already started and for the Half Sword report where rendering froze during detach.

## Performance invariant

Compatibility is additive, not a new wrapper around every frame.

For a proven native D3D11/D3D12 game:

```text
compatFrames = 0
legacyCopies = 0
```

No legacy transfer path should initialize or execute for those routes.

The Feature 18 color input/output path remains full resolution. Lower-resolution work is limited to auxiliary analysis where applicable.

## Known limitations

v0.4.0 remains experimental. Renderer compatibility does not guarantee that a game exposes trustworthy motion vectors, depth, camera matrices, or HDR semantics. Vulkan external-memory support must be available/enabled; OpenGL interop depends on the active context/driver; classic D3D9 has inherently greater transfer overhead; multi-GPU/cross-adapter configurations and unusual exclusive-fullscreen/recreation flows may need additional work.

There is no desktop/screen-capture fallback, and UniversalDLSS5 does not bypass anti-cheat, DRM, protected-process, or module-signature policy.

# v0.2.8 Feature-18 output/lifecycle debug fix

Date: 2026-09-12

Observed symptom after the previous ghosting/color patch: final output can become almost black, with only moving/high-change edges visible.

The final compositor does not bind the motion texture in place of the neural output. In `post.hlsl`, the resources are distinct: neural output is `t0`; motion is `t3`; motion is rendered only when `DebugView == Motion`.

Two concrete issues were found during a re-audit against a known working Feature-18 D3D12 sequence:

1. `CreateFeature` and the first `EvaluateFeature` were recorded into the same command list without first submitting/completing the one-time feature initialization work. The fixed path submits the creation list, waits for its D3D12 fence once, resets the command list, and only then performs the first evaluation.
2. The D3D11 producer fence signal was not explicitly flushed before the D3D12 queue waited on it. The fixed path calls `Flush()` immediately after `ID3D11DeviceContext4::Signal`.

A new `Raw neural output` debug view was added. This makes it possible to distinguish three cases without guessing:

- `Original` correct + `Raw neural output` correct -> problem is in UniversalDLSS5 post-composition.
- `Original` correct + `Raw neural output` black/edge-only -> Feature-18 input/lifecycle/output path is the problem.
- `Motion vectors` looks like the visible frame while `Raw neural output` is normal -> debug-view selection/state is wrong.

The skin-structure default is also restored to `-1` (runtime auto sentinel) rather than `0`. v7 profiles that still contain the temporary `0` default are migrated to `-1`.
